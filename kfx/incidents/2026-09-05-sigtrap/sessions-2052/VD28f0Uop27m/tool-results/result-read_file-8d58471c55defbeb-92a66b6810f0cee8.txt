70 	
71 	The fork is a thin patch stack rebased onto upstream `main`.
72 	
73 	* One intent per commit. Do not mix fork patches with unrelated work; each patch must be individually keepable or droppable during a rebase.
74 	* Every fork commit carries a body explaining its intent and its conflict policy. During a rebase, read the commit body of the conflicting patch first.
75 	* Prefer additive seams (environment variables, config, new files) over deleting or rewriting upstream code, so patches rarely conflict.
76 	* Enable `git rerere` locally (`git config rerere.enabled true`) so a conflict resolved once replays automatically. Agents must not change git config themselves; ask the user to run it.
77 	* Upstream hot zones that fork goals touch: `src/builtins/tools.zig`, `src/core/tooling/`, `src/gateway/`, `src/core/config/config_runtime.zig`. Expect conflicts there and resolve in favor of the patch's stated policy.
