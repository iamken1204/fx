# Provider Attempt Ownership Audit

Static audit of checkout `5b5dc8ad1856388325664fbf87a3949d543fcd82`, 2026-09-05. No concrete write-after-free was found in the bounded Codex request lifetime examined here. This does not establish that the program is memory-safe or identify the writer of the poisoned malloc block. No production code changed; no new runtime reproduction or tests were run for this audit.

## Confirmed Source Facts

- Each provider-loop iteration creates its own `c_allocator`-backed arena and defers destruction ([orchestrator.zig:5497](../../../src/core/agent/runtime/orchestrator.zig#L5497)). `streamModelCompletion` receives that allocator, but usage receives the separate `deps.usage_allocator` ([orchestrator.zig:6018](../../../src/core/agent/runtime/orchestrator.zig#L6018)). The normal exit copies the result before leaving the iteration ([orchestrator.zig:7177](../../../src/core/agent/runtime/orchestrator.zig#L7177)). The copy includes completion strings/tool calls, deferred-usage strings, and failure diagnostics ([orchestrator.zig:3366](../../../src/core/agent/runtime/orchestrator.zig#L3366), [types.zig:2547](../../../src/core/shared/types.zig#L2547)). This is a deep copy of the inspected slice-bearing fields.
- Codex streaming owns a local HTTP client and request. After connection, its cancellation watcher is stopped and joined by a later defer, therefore before request/client destruction ([openai_codex.zig:295](../../../src/gateway/openai_codex.zig#L295), [openai_codex.zig:326](../../../src/gateway/openai_codex.zig#L326)). The watcher only polls control state and shuts down the socket; it does not retain the provider allocator ([client.zig:1950](../../../src/gateway/client.zig#L1950)).
- The bounded operation has three Select tasks. Every post-spawn return either drains cancellation or cancels the already-started tasks on spawn failure. Successful late results are deinitialized while the supplied allocator remains alive ([client.zig:1843](../../../src/gateway/client.zig#L1843)). In the installed Zig 0.16.0 source, `std/Io.zig:1509` calls `group.cancel` before reading a result. Its documented contract blocks until all tasks finish. `std/Io/net/HostName.zig:284` cancels the connection future before releasing stack queues; `:343` creates the DNS future and `:347` cancels it before leaving `connectMany`. `std/Io/Threaded.zig:2484` waits for a pending future before copying its result and destroying it. These source paths do not support a DNS task continuing after the attempt arena is destroyed.
- Codex supplies exact subscription usage ([openai_codex.zig:377](../../../src/gateway/openai_codex.zig#L377)). The asynchronous deferred reconciliation branches in [gateway_step.zig:87](../../../src/core/agent/runtime/gateway_step.zig#L87) therefore do not run for this successful Codex path.
- Parallel tool slots each own an arena. All worker threads join before result duplication, and slot arenas are destroyed afterward ([parallel_execution.zig:180](../../../src/core/agent/runtime/parallel_execution.zig#L180), [:201](../../../src/core/agent/runtime/parallel_execution.zig#L201), [:251](../../../src/core/agent/runtime/parallel_execution.zig#L251)). The inner per-call arena does end sooner, at the return from `parallelHookExecute` ([parallel_execution.zig:283](../../../src/core/agent/runtime/parallel_execution.zig#L283)); dispatch copies output, tool-result memory, and status detail to the slot allocator ([tool_runtime.zig:858](../../../src/core/tooling/tool_runtime.zig#L858)).

Zig standard-library references above are to `/opt/homebrew/Cellar/zig/0.16.0_1/lib/zig/`. They describe the locally installed compiler, not proof of the exact compiler used for every historical binary.

## Limits And Hypotheses

The shell metadata omission remains a latent ownership hazard: `publishSnapshotMetadata` allocates `command_result_json` on call scratch ([shell.zig:1415](../../../src/tools/shell/shell.zig#L1415)), dispatch does not copy it, and parallel fan-in would copy it after that scratch dies ([parallel_execution.zig:350](../../../src/core/agent/runtime/parallel_execution.zig#L350)). However, the actual parallel classifier excludes shell ([parallel_execution.zig:17](../../../src/core/agent/runtime/parallel_execution.zig#L17)). This is not a demonstrated incident path, and copying stale bytes would first establish a read-after-free, not the writer of a free-block corruption.

The audit checked ownership at provider/tool boundaries and async network teardown. It did not exhaustively prove every downstream UI callback, provider parser, shared runtime object, allocator implementation, or libc resolver operation free of races or buffer overflows.

An allocation/free stack from `malloc_history` identifies the corrupted block's owner. It does **not** by itself identify its later writer or settle fork versus upstream responsibility: another component can overwrite that block through a stale pointer or an adjacent overflow. A write watchpoint, allocator poisoning with an earlier fault, or a reproducer exposing the invalid store is needed to assign the writer.
